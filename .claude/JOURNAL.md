1. **Task - Project from the steel dark theme** (v0.1.0): Created `jupyterlab_mechanicum_dark_theme` as a sibling of `jupyterlab_galaxalabs_steel_dark_theme`<br>
   **Result**: The user ordered a parallel theme in the Adeptus Mechanicum look. The tracked files of the steel theme were copied without its journal, changelog, release notes and screenshot, and every package name was changed to `jupyterlab_mechanicum_dark_theme`; the theme registers as `Mechanicum Dark Theme` in `src/index.ts`. `style/scrollbars.css` was left out because the steel theme never imports it. The folder is its own git repository on branch `main`; nothing is committed and no remote exists. `.claude/CLAUDE.md` states that the names and symbols follow Warhammer 40,000, so publishing is the owner's decision.

2. **Task - Colours** (v0.1.1): Set the Mechanicum palette in `style/variables.css` with measured contrast<br>
   **Result**: The user asked for a theme that stays functional and is easy on the eyes. Text areas are a warm near-black (`#181211`), panels oxblood (`#241615`), text is parchment and never white, the brand colour is gold and the accent verdigris. A script measured every text and code colour against the backgrounds: body text 10 or more, every code colour 4.8 or more on the editor background. Rows that JupyterLab fills with the brand colour (file list, command palette, completer) are crimson with a gold thread, because a gold block glares. Dialog buttons take their colours through `--jp-accept-color-*`, `--jp-reject-color-*` and `--jp-warn-color-*`, since JupyterLab's own button rules are more specific than a theme rule.

3. **Task - Ornament** (v0.1.2): Wrote `style/mechanicum.css` and the images in `style/images/`<br>
   **Result**: The user asked for the full Mechanicum embroidery, as extreme as possible. Ornament sits on the frame only and nothing moves. SVG drawings made by script: gear, skull-in-gear emblem, embroidered band, fringe, purity seal, a frieze of Latin mottos and `AVE OMNISSIAH` in binary. Raster images reduced from the generated textures of `funcraft/w40k-mechanicum/resources/assets`: altar cloth, drape, hanging, cloth texture, iron skulls; the drape's white ground was removed. They dress the top bar, activity bars, tabs, launcher, notebook headings, active cell, menus, dialogs and status bar. Lesson: a preview that injects styles must append them to the body, because JupyterLab puts the theme's link there and the later sheet wins. `jlpm lint:check` passes; `make install` built and installed the theme; headless Chrome showed launcher, notebook, editor, menu, palette and dialog without page errors.

5. **Task - Launcher strip designed with the image model** (v0.1.4): Replaced the SVG strip with a strip generated by Z-Image-Turbo<br>
   **Result**: The user found the drawn SVG skull cartoon-like and ordered a proper image model. New `tools/strip.py` generates six drafts per part with Z-Image-Turbo (9 steps, guidance 0, cached weights, GPU 1, the Python of `funcraft/w40k-mechanicum/.venv-moge`) into the ignored `wip/strip/` and composes the chosen drafts at twice the strip height into `strip-centre.jpg`, `strip-plate.jpg` and `strip-cap.jpg`. The centre is one 2048 x 320 draft: riveted steel with `ADEPTUS`, the Cog Mechanicum (a skull half bone, half machine with a red lens, in a gear) and `MECHANICUS` in gold. Drafts 1 and 3 misspelled `MECHANICUS`; draft 5 was chosen after every letter was read. The plate is mirrored so it repeats without a seam, and the steel is darkened to 82 %. The SVG strip files were deleted. The README gained a warning that the author expects nobody to use the theme for more than 5 minutes.

9. **Task - Thin scrollbars** (v1.0.3): Added `* { scrollbar-width: thin; }` at the end of `style/custom.css`<br>
    **Result**: Request was to borrow the scrollbar look of the MOTD tab (`jupyterlab_galaxahub_motd_extension`), whose columns set only `scrollbar-width: thin` in `style/base.css`. The property is not inherited, so the theme rule uses the universal selector; a rule on `:root` would thin the root scroller alone. Colours unchanged: the theme registers `themeScrollbars: true`, so core applies `--jp-scrollbar-thumb-color` and `--jp-scrollbar-background-color` through `scrollbar-color`. Measured in headless Chrome 154 against a separate JupyterLab 4.6.4 instance with its own settings directory: the file browser list and the Markdown preview scrollbars were 15px wide before and 10px after. stylelint clean. Firefox, Safari and Chrome on Windows not tested.
